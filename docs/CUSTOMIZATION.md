# Customise for your server

## The two places you edit

| What you want to change | Edit here | Apply it |
| --- | --- | --- |
| Which NPC/tree uses a theme | `addons/themes/config.cpp` | Repack and update server/clients |
| Faction initials, heading, footer, colours | `addons/themes/config.cpp` | Repack and update server/clients |
| Frame artwork | `addons/themes/GUI/textures/` and its config path | Repack and update server/clients |
| Menu arrangement | Layouts and, where positioned in code, `OE_DialogueWindowMenu.c` | Repack and update server/clients |
| NPC speech, response wording, conversation branches | Framework dialogue JSON in the server profile | Restart server; no theme PBO rebuild |
| Quest objectives, rewards and quest NPC setup | Your Expansion server configuration | Follow Expansion's configuration workflow |

Framework files live under `$profile:\DialogFramework\` in the inspected v1.3.0 release. Note the spelling **DialogFramework** in this directory. Use the examples and field reference generated by your installed framework release.

## 1. Match your NPC and dialogue tree

Open `addons/themes/config.cpp`, then find `CfgOperationExileDialogueThemes`.

| Included theme | NPC ID | Dialogue tree ID | Extra matching rule |
| --- | --- | --- | --- |
| UCF | 5 | 5 | None |
| CCA | 4 | 4 | None |
| GreenMountain | 1 | 1 | Also matches NPC 6 with tree 6 |
| Traders | — | — | Every recognised framework trader session |

The two IDs must **both** match. `npcID` is the NPC identity used by Dialogue Framework; for an Expansion quest NPC, match its Expansion NPC ID. `treeID` is the active dialogue JSON's top-level `ID`. It is **not the quest ID, root node ID or a response node ID**.

For example, if your quest NPC has ID 12 and its active dialogue tree starts with `"ID": 25`, edit the UCF block:

```cpp
enabled = 1;
npcID = 12;
treeID = 25;
```

The IDs need not be equal. Multiple conversations on the same NPC may have different tree IDs and need separate matching theme entries.

For GM, remove `testNpcID = 6;` and `testTreeID = 6;` if you do not need the original test NPC. Set any unwanted theme to `enabled = 0;`. Keep matching pairs unique: the resolver returns the first enabled matching entry.

NPC conversations are typically under `DialogFramework/Dialogues/NPC_<id>/`; trader conversations are under `Trader_<name>/`. This addon supplies no conversation JSON or NPC spawn records. Adapt your working framework example there to change speech and responses; assigning a theme alone does not create a conversation.

## 2. Change the branding

Within the chosen theme class, edit:

```cpp
code = "NCR";
fullName = "NORTH COAST RANGERS";
label = "RANGER OUTPOST";
subtitle = "YOUR SERVER / LOCAL CONTACT";
```

Keep `code` short so it fits the left header. `label` is the main header and `subtitle` is the footer. The NPC speaker name and spoken text come from the framework/NPC setup, not these labels.

For the displayed mod name, change `name`, `tooltip` and `overview` in root `mod.cpp`, plus the displayed `name` in `CfgMods`. Preserve original authorship credit when adding your own. Keep version descriptions consistent if you release a changed build; the script log also contains `v0.3.1`.

You can change display branding without renaming the internal classes or prefix. If you need a separately namespaced fork, update `$PBOPREFIX$`, script-module paths, every texture/layout path, config class identities and custom script class references consistently. Do not load two copies that both modify `DialogueWindowMenu` without checking their interaction.

## 3. Change colours

Colours use **`{alpha, red, green, blue}`**, with integer values from 0 to 255. Alpha 255 is fully opaque; 0 is transparent. This is ARGB order, not RGBA.

```cpp
HeaderColor[] = {255, 25, 45, 35};
AccentColor[] = {255, 180, 155, 90};
SpeakerTextColor[] = {255, 235, 235, 220};
```

| Field | Controls |
| --- | --- |
| `BackgroundColor` | Inner dialogue background |
| `ResponseBackgroundColor` | Response backgrounds |
| `HoverBorderColor` | Hover highlight |
| `SpeakerNameColor` | NPC speaker name |
| `SpeakerTextColor` | NPC speech |
| `ResponseTextColor` | Player reply text |
| `RewardSelectedColor` | Selected reward background |
| `WindowBorderColor` | Border/divider colour used by the themed menu |
| `HeaderColor` | Header plate |
| `AccentColor` | Accent details and reply rails |
| `FrameTintColor` | Optional tint multiplied onto the frame texture |
| `BrandColor` | Optional branding/control colour override |

To show a frame without colour tinting, use `FrameTintColor[] = {255, 255, 255, 255};` or omit that field. UCF deliberately includes a dark tint. Invalid colour arrays fall back rather than applying the invalid values.

## 4. Replace a frame

The four used assets are `ucf_frame_ca.paa`, `cca_frame_ca.paa`, `gm_frame_ca.paa` and `trader_frame_ca.paa` in `GUI/textures`.

Create your artwork with a transparent outer area and convert it to a DayZ-compatible PAA with alpha support using your texture tools. Preserve the existing frame proportions so borders align with the menu. Layered PSD/PNG originals were not contained in the supplied PBO.

Place the new texture in the same directory and update the theme:

```cpp
frameTexture = "operationexiledialoguethemes/addons/themes/GUI/textures/rangers_frame_ca.paa";
```

This is a virtual PBO path, not a Windows drive path. Match the filename and case exactly. Repack, deploy and check transparency, readability and alignment in game.

## 5. Add another theme

Copy an entire ordinary NPC theme class, such as `class UCF`, inside `CfgOperationExileDialogueThemes`. Give it a unique class name, such as `class Rangers`, then change its ID pair, text, colours and texture path. The script discovers theme classes automatically.

Copy all its colour fields. Remove any test-ID fields you do not intend to keep. Do not add `allTraders = 1` to an ordinary NPC theme.

This version supports one general trader style through `allTraders = 1`. It does **not** look up trader names in the theme config. Multiple trader theme classes do not assign different traders; the first matching general trader theme wins. Per-trader selection requires extending `OE_ResolveTheme` and `OE_DialogueTheme.Resolve` using the framework's trader identity.

## 6. Adjust layout and size

`HeaderOffsetY` is an optional per-theme vertical offset, clamped from `0` to `0.05`. GM uses `0.04` to lower the header. The code also shifts/shrinks the body to accommodate it.

The overall themed panel size is set in `OE_DialogueTheme.c`, inside `MakeLocalConfig`:

```cpp
result.PanelWidth = 0.64;
result.PanelHeight = 0.52;
```

Those values override the framework's width/height settings for themed windows. Position and several other preferences are copied from the framework; a saved player position can override the server position.

For deeper changes, edit `GUI/layouts/dialogue_menu*.layout` and `dialogue_response_button*.layout`. Keep the default, `_compact`, `_large` and `_light` variants because the script selects them using the framework's layout suffix. Preserve widget names referenced by either script. `OE_ApplyChrome` also sets header/body coordinates in code, so changing those coordinates only in a layout may have no effect.

Leave the framework's `MenuConfig.json` `LayoutOverride` empty (`""`) when using this addon. An explicit override prevents theme selection in this version.

Retest long dialogue, response wrapping/scrolling, reward controls and small screen resolutions after layout changes. Use [Build and install](BUILD.md) when ready to repack.
